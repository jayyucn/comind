## 编译检查规则

### 规则要求
所有代码修改必须经过严格的编译检查，确保修改后的代码在当前项目指定的编译环境中能够成功编译。

### 执行步骤
1. **提交前检查**: 开发人员在提交代码前必须执行完整的编译流程
   ```bash
   npm run build
   ```

2. **验证编译结果**: 确保编译过程不产生任何语法错误、类型错误或依赖错误

3. **代码审查确认**: 在代码审查过程中再次确认编译状态

### 适用范围
- 业务逻辑代码（`.ts`, `.vue`）
- 配置文件（`.json`, `.tsconfig.json`）
- 测试代码（`.test.ts`, `.spec.ts`）
- 浏览器自动化测试代码（`.e2e.ts`, `.spec.ts`）

### 检查标准
- ✅ TypeScript 类型检查通过（`vue-tsc -b`）
- ✅ Vite 构建成功（`vite build`）
- ✅ 无语法错误
- ✅ 无依赖错误
- ✅ 单元测试通过（`npm run test`）
- ✅ 浏览器自动化测试通过（`npm run test:e2e`）
- ✅ 前端功能验证通过（基于 webapp-testing 技能）
- ✅ UI 行为调试无异常
- ✅ 浏览器日志无错误

### 浏览器自动化测试要求
1. **测试覆盖**: 关键用户交互流程必须有对应的自动化测试覆盖
2. **测试环境**: 使用 Playwright 进行浏览器自动化测试
3. **测试验证**: 包括页面导航、元素交互、表单提交、状态验证等
4. **截图验证**: 关键页面节点需进行截图对比验证

### 违规处理
未通过编译检查的代码不得提交到版本控制系统。
