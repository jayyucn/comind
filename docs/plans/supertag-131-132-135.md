# Supertag 三个子系统实现计划（#131 / #132 / #135）

> 父规格：#125 超级标签分类层（ADR-0049）。前置：T1 #129（标签页种/列表过滤，已落）、T2 #130（`applyTag`/`resolveTagMembers` + 保留类型，已落）。
> 依赖底座：`useTagStore`（T2）、`useRelationshipTypes.RESERVED_RELATIONSHIP_TYPES = ['tag','extend']`、`Page.type='tag'`、`client.getOutlinks/getBacklinks/getProperties/setProperty/deletePageCascade`。

## 子系统 A — #131 标签模板定义 + 字段注入渲染（T3）

**范围**：模板存储、派生字段计算、注入渲染。字段为**派生不物化**（ADR-0049 D5/D6）。

### 设计
- **`TagFieldSpec`**（可序列化字段描述符，存库形态）= `{ key, label, type: PropertyType, options?, sortOrder? }`。不含 `FieldDescriptor.get` 函数（无法 JSON 化）；渲染取值时改读 block 真实属性。复用现有字段词汇（key/label/type/options）。
- **模板存储**：存于 tag-page 区块的 `template` 属性（JSON 字符串，type=`string`），单一数据源。读写经 `client.setProperty/getProperties`（绕过 property-store 定义机制，避免污染用户属性列表）。
- **`resolveInheritance(tagPageId)`**：沿 `relationshipType='extend'` 出边 BFS 收集祖先，带 `visited` 防环。
- **`effectiveFields(tagPageId)`**：本标签模板 + 继承链合并；冲突就近覆盖（自身 > 直接父 > 更远祖先）。纯异步函数。
- **`effectiveFieldsForBlock(blockId)`**：收集 block 的 `relationshipType='tag'` 出边（按 `created_at` 升序 = 先贴先胜），逐标签 `effectiveFields` 合并；**E1 同名字段冲突 = 先应用（最早 created_at）的标签胜**，确定性兜底按 tagPageId 排序。
- **渲染不物化**：`TagFieldsPanel.vue` 读取 `effectiveFieldsForBlock` 派生字段 + 读 block 真实属性值展示；仅当用户显式填值才 `setProperty` 写真实属性。`applyTag` 本身不写任何模板字段 → 派生验证天然成立。
- **模板编辑 UI**：`TagTemplateEditor.vue` 复用 `FieldManagerPanel` 的结构化面板套路（VueDraggable + `force-fallback` + ghost class、`__test_setOrder`/`onDragEnd` 测试接缝、行内增/删/改），编辑 `TagFieldSpec[]` 并每次变更即 `setTagTemplate` 落库。**不直接复用 `FieldManagerPanel` 组件本身**：其 props 是 `FieldDescriptor[]`（含不可 JSON 化的 `get` 函数）且语义为 per-tab 显隐 + 全局增删，与模板编辑（单一有序列表）不匹配；照搬会逼出 `get: () => ''` 之类的假字段与无意义的显隐开关。
  - 挂载点：tag-page 正文顶部（`Page/index.vue` 内 `isTagPage` 门控），默认折叠以免占满正文。
  - 有意省略：搜索框（模板通常 <10 字段）、编辑开关（删除仅作用于本模板，非全局）。
- **只读路径不得建块**（AC-2 的推论）：`resolveTagPageBlockId(tagPageId, create=false)` 为默认——读模板发生在渲染期（`effectiveFields` → `getTagTemplate`），若沿用旧的「无 blockId 就 `ensurePageBlocks` + `flushSave`」，则**只要渲染一个贴了标签的 block 就会给标签页建块落库**。改为只认 `page.blockId` 或 store 中已缓存的本页根块，缺失即按「无模板」返回 `[]`；只有写入路径（`setTagTemplate`）传 `create=true`。
- **字段类型词汇**：`TagFieldType = PropertyType | 'select' | 'multiSelect'`（排除 `'text'`——`PropertyType` 里没有它）；`tagFieldValueType()` 把 select→`string`、multiSelect→`array` 映射到落库类型。
- **不改 key**：`key` 是值的存储键，编辑器只允许新增时设定，不做重命名（避免孤立既有值）。

### 改动文件

- `src/components/Block/index.vue`：属性带内挂载 `TagFieldsPanel`。
- `src/components/TagTemplateEditor.vue`（新）：模板结构化编辑面板。

## 子系统 B — #132 打标签输入 UX（`#foo` 拦截）（T4）

**范围**：编辑器内 `#foo` 触发标签选择/创建，调用 `applyTag`。

### 设计
- **`TagInputExtension`**（镜像 `SlashCommandExtension`）：`handleTextInput` 监 `#`；护栏 `isTagTriggerContext`（不在 URL、非 `# ` 标题）。命中则 `dispatchEvent(new CustomEvent('tag-input-trigger', {detail:{view, position, range, query}}))`。纯函数 `parseTagQuery(textBefore, caret)` 抽取 `#word`（可单测，呼应 E5）。
- **挂载**：`Editor.vue` extensions 列表加入 `TagInputExtension`。
- **`TagSelectMenu.vue`**（镜像 `SlashCommandMenu`）：监听 `tag-input-trigger`；列出已有 tag-page（按 query 过滤）+「创建 #X」；选中/回车：`getPageByTitle` 命中则 `applyTag`，否则 `createTagPage` 后 `applyTag`；随后删除编辑器内 `#word` 文本（`editor.chain().deleteRange(range).run()`）。
- **不冲突（E5）**：`#` 触发与 `/` 斜杠命令、`RelationshipMenu`（`[[`/关系触发）语义正交——`#` 仅当非 URL、非标题时触发；`RelationshipTriggerExtension` 走 `[[` 前缀，互不打扰。

- `src/components/TagSelectMenu.vue`（新）：标签选择器。

## 子系统 C — #135 删标签级联清理（T7）

**范围**：删 tag-page 时级联清其成员 `tag` Link 与作为父标签的 `extend` Link，无悬空。

### 设计
- **复用核心级联**：`block_write::delete_page_cascade` 已删除 (1) 作为 target 的全部 Link（`delete_by_target_page_id`，含成员 `tag` Link 与作为父标签的 `extend` Link）、(2) block 级联删除作为 source 的 `extend` Link（`delete_by_source_block_id`）。即硬删 tag-page 已无悬空。
- **`useTagStore.deleteTagPage(tagPageId)`**：护栏（须 `type='tag'`）→ 委托 `usePageStore().deletePage`（走 `deletePageCascade`）。显式收口意图、留注释呼应项目 cascade 关注。
- **不软删 tag-page**：tag 删除走硬级联，避免 `softDeletePage` 仅标 deleted 残留悬空 Link。
- **单测（E3）**：建标签 → `applyTag` 成员 → 建 `extend` 链接（子→父）→ `deleteTagPage` → 断言 `getBacklinks` 无 `tag`/`extend` 悬空。

- `src/composables/useTagStore.ts`：扩展 T7（`deleteTagPage`）。
- `src/composables/useTagStore.delete.test.ts`（新，S2/extend 接缝）。

## 跨切面修正（实现期发现的阻塞项，必需）

**问题**：`block_service` 的 create/update（及 `content_parse_service` 空内容分支）走
`sync_links_for_block`，原本「先删该 block 全部出链，再按 content 重建」。而 `tag`/`extend`
是**程序化写入、非内容派生**的链接（ADR-0049 D4）——于是**任何一次 block 保存都会抹掉已贴的
标签 / 继承链接**。这直接击穿 #131（贴标签→编辑即丢）、#132（删 `#word` 文本触发保存→刚贴的标签被清）、
#135（无链接可清）。

**修正**（最小改动，保留 3 处调用语义）：
- `LinkService::sync_links_for_block`：只删**非保留**关系类型的链接，再建内容派生链接；
  新增 `RESERVED_RELATIONSHIP_TYPES = ["tag","extend"]` 与 `is_reserved_relationship`。
- `ContentParseService::sync_links_for_block`（无内部链接分支）：改为
  `LinkService::sync_links_for_block(..., &[])`（保留 tag/extend），不再 `delete_by_source_block_id`。
- `BlockService::delete`：整块删除须清**全部**出链（含保留），改回直接
  `LinkService::delete_by_source_block_id`（不走保留语义的 sync）。

改动后需 `npm run wasm:build` 重建 wasm 供 vitest/Tauri 使用。
