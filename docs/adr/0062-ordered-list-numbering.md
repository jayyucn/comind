# 0062 有序列表序号的推导与锚点

- Status: accepted
- Date: 2026-11-23
- 关联: ADR-0009（分层边界）、ADR-0025（块复制粘贴）、ADR-0039（块入口与段落样式）、ADR-0046（撤销历史）

## Context

有序列表不是块类型，而是 bullet 块正文的前缀（`parseParagraphStyle` 里的 `ol`）。序号此前**只是字面数字**，没有任何一层负责它的连续性：

- 渲染态（`BulletRender`）、编辑态标记（`ParagraphStylePreviewExtension`）、拆分续行（`listContinuationPrefix`）各自从正文里读字面数字，谁也不推导。
- 结构一变就失真：删掉中间项得到 `1, 3, 4`；缩进、反缩进、拖动、粘贴之后同段落里的项各说各话；拆分时新块取「本块字面 + 1」，若本块字面已过期，错位会继续向后传染。
- 菜单把块切成有序列表时恒写 `1. `，插在已有列表中间就从 1 重新起算。

正文是唯一被渲染、被检索、被导出、被 AI 上下文读取的东西，序号错乱会同时出现在阅读态、查询预览和导出结果里。前缀语法本身（列表 = `1. ` / `- `，标题 = `# `）是既有约定，不引入块类型。

## 决策

### D1 真源是 content：推导结果写回正文

序号由「段 + 锚点」推导出来，**写回 `content`**，而不是只在渲染层算一遍再显示。

理由：字面序号同时被五处消费（渲染、编辑态标记、续行、查询/导出、复制粘贴载荷）。只要有一处保留字面、一处用派生值，就必然出现「阅读态 3、编辑态 4」这类两处真相。写回让所有消费方继续读字面，改动面最小。

写回只发生在序号**确实该变**的块上：`changed` 为 false 的块不产生任何写入、不触发落库（零变更 = 零副作用）。

### D2 段落与推导规则

- **段** = 同一父块下**连续**的有序列表块；遇到正文 / 标题 / 无序列表即断（各自成段）。子块是独立段，各自从自己的段首起算。
- 段首起点 = `段首锚点 ?? 段首字面`。取字面是为了让存量文档里「从 5 开始」的列表不被改写成 `1, 2, 3`。
- 逐项 `desired = cur`，然后 `cur += 1`；段中若遇到锚点则 `cur = 锚点` 重新起算。

纯函数实现见 `src/composables/ordered-list-index.ts`（`planOrderedListNumbering`），不认识 store。

### D3 锚点：`format.olIndex`

锚点是挂在块上的**绝对序号**（不是「+1 偏置」），存 `Block.format.olIndex`（`format` 是 JSON 列，无需 schema 变更）。

生灭规则：

| 时机 | 行为 |
|---|---|
| 用户在块里手写序号，且新字面 ≠ 该位置的自然推导值 | 写入锚点 = 新字面（跳号固定下来，后续跟着变） |
| 手写值回到自然推导值 | 清掉锚点 |
| 段首项被删除 | 接替段首的块写入锚点 = 1（回到 1 重排）；接替者已有锚点则保留 |
| 跨父搬移（缩进 / 反缩进 / 拖动） | 清掉锚点（锚点只在本父层内有意义） |

「前面不动、允许断点」由此成立：锚点之前的增删不影响锚点自身，段内可以合法出现 `1, 10, 11`。

### D4 写回机器：平移派生数据，不动别的

改一个序号只改首段数字，但两处派生数据必须跟着走：

1. **`format.inlineMarks`**：正文长度变化且未显式传 marks 时，`updateBlockContent` 会清空行内格式——不清洗偏移就等于「删一条列表项顺手吃掉后面所有粗体」。
2. **`renderSegments`**：段边界按旧 content 计算。前缀差 ±1 个字符时整体平移即可；沿用 `updateBlockContent` 的「置 undefined」会让该块在落库回填前退回纯文本渲染（`[[页]]` 的括号闪一下）。完全落进前缀区的段丢弃。

**正在编辑（活动）的块跳过写回**：内容由编辑器自己持有，写进 store 会被它 300ms 后的下一次防抖保存整段覆盖；但仍参与推导，后续块按推导值续号。

### D5 触发点与合并窗口

| 入口 | 触发方式 |
|---|---|
| 正文变化（含打字、斜杠命令、粘贴后的清空等） | `updateBlockContent` 尾部调度（仅当新/旧内容是 ol） |
| 删除块 | `deleteBlocks` 尾部调度（段首锚定在删除前完成） |
| 缩进 / 反缩进 | `indent` / `outdent`（顺带清锚点） |
| 拖动 | `BlockList.handleDragEnd`（`syncTreeToStore` 内清锚点） |
| 粘贴 / 跨页搬移 | `pasteBlocks` / `pasteBlocksWithOp` 尾部调度 |

同一页的调度按 150ms 合并成一次推导。窗口只影响落库与其它块的显示，正在编辑的块本就跳过。

### D6 各入口向调度器要号

- **Enter 续行**：`listContinuationPrefix` 取 `nextOrderedListIndex`（本块推导值 + 1），不再用字面 + 1。空列表项按既有语义退出列表。
- **菜单转有序列表**：`orderedListIndexForNew`——前面接着连续的有序列表就顺延，否则从 1 起。
- **粘贴**：载荷不带锚点，落到新位置后整段顺排。

### D7 撤销粒度

推导写入走 store 的同一批 `_scheduleSave`，与触发它的那次操作落在同一个整页快照里（ADR-0046 的封口时机不变），因此「删一条列表项」和它引起的重排是一步撤销。

## 已否决的方案

- **只改显示（渲染态派生数字，不回写 content）**：编辑态前缀里仍是旧字面，用户看到的号码与阅读态不一致；复制/导出/查询预览读的也是字面。两处真相的成本高于写回。
- **引入有序列表块类型（或 ProseMirror ordered list 节点）**：前缀语法是既有约定，变成块类型要迁移全部存量数据、并为 `1. ` 写一遍输入/删除/折叠规则；收益只是「序号变成结构数据」，而锚点已经用一行 `format` 提供同样的能力。
- **每次输入即时全页重排**：打字路径上每敲一个字符扫一遍同页块会带来可见抖动，且会与编辑器自己的保存互相覆盖。
- **写回时清空 `renderSegments`（复用 `updateBlockContent` 默认行为）**：改号会让整块短暂退回纯文本渲染，含 `[[ ]]` / `#tag` 的列表项闪一下括号。

## 后果 / 待办

- 存量文档打开时不重排；**第一次被触发**（编辑 / 删除 / 缩进 / 拖动 / 粘贴）时整段对齐。历史遗留的、未落锚点的手写跳号会在这一刻被抹平为顺排——要保留必须在触发前手写一次该序号。
- `format.olIndex` 随块复制/粘贴载荷一起走，但**粘贴会丢弃锚点**（`pasteBlocks` 建块不带锚点）：从别处粘来的 `10. ` 按落点顺排。若将来需要保留，在载荷里带 `format` 的锚点并让推导层识别即可。
- 段首字面作起始值 ⇒ 段内出现跳号后，**段首不会回溯**：`1, 10, 11` 合法。
- 已知缺口（既有）：同页剪切粘贴的撤销仍是两步。
