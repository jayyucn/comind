# Ideas 页真快照：以快照取代冻结

任务块创建落入今日 ideas 页后，与"历史页不可变"产生结构性冲突（跨天遗留、冻结豁免、续办迁移等复杂性皆源于此）。最终决定以**快照取代冻结**作为历史诚实性的存储级保证：每个 ideas 页跨天后在启动时**惰性物化**为不可变快照（`page_snapshots(page_id, date, version, content_json)`，含块树与**当日属性值**，幂等键 page_id，永不重物化）；历史 ideas 页的一切**页面渲染**统一走快照；历史页的**活数据不再冻结**——块级通路（TaskHub 卡片、BlockModal）对历史页块保持完全可编辑，因为编辑只改活数据、不触碰快照，当日记录不受影响。不迁出、无独立任务容器页，`useIdeasFreeze` 退役。快照逻辑放 comind-core，sqlite/sqljs 双端共享。

## Considered Options

- **事件溯源**（记录每次变更、可重建任意时刻）：终极真快照，工程量大，拒绝——个人日记体量下物化已满足诉求。
- **冻结渲染活数据**（既有 `useIdeasFreeze` 路线）：冻结只是 UI 契约而非存储保证，属性通路可改历史页状态。被本方案取代：快照成为存储级保证后，冻结失去存在理由。
- **快照 + 任务迁出到独立容器页**（本 ADR 初版）：为让活任务脱离冻结环境而把块搬到「任务收集」页。后认识到快照本身已保证历史不可变，活块可安全保持可编辑，迁出纯属多余——**由无迁出模型取代**。
- **块级冻结豁免 / 续办迁移 / 物理搬移昨日任务**：分别破坏历史不可变、时间锚定，或伪造产生日期，均拒绝。
- **快照进 SyncTable**：先不进 Sync，表结构对齐同步约定预留；多设备下"物化时刻 ≠ 午夜"的时间差为已知限制。

## Consequences

- **页面渲染与块级通路分权**：历史 ideas 页页面渲染 = 快照只读（树折叠、bullet 开快照只读 BlockModal、[[wiki]] 跳转、图片只读缩放）；TaskHub/BlockModal 直达活块 = 可编辑（内容、子块追加、属性）。BlockModal 按上下文分两态：快照上下文只读、活块上下文可编辑——不再按页面日期判定。
- 同一历史任务：快照视图显示**当日**状态，TaskHub 显示**当前**状态。分歧即设计（存储/快照分离），非缺陷。
- `useIdeasFreeze` 退役：BlockModal 不再按页面日期锁只读；实现时清理其调用点（BlockList 等渲染方已无历史页活数据入口）。
- 「任务收集」页成为遗留容器：原样保留，不再有新块落入；存量任务仍在 TaskHub 全库查询中可见。
- 反链照常工作：历史页活数据继续存在，其 wiki link 照常入链；快照渲染不产生重复反链。
- 历史任务命中 `queryIncompleteTasks`（Todo/Doing 且 page.type='ideas'），通知管线天然覆盖，无需迁出即保持可发现。
- 多设备：各设备各自物化，"物化时刻 ≠ 午夜"的属性值时间差为已知限制；预留 Sync 接入。
