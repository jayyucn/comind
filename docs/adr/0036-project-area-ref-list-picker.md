# ADR-0036: project/area 属性选择器 —— 自由字符串 + 全量快照派生

- 状态：已采纳（Accepted）
- 日期：2026-08-25
- 范围：
  - `src/components/Block/PropertyDisplay.vue`（bottom-of-block 的 icon-text 内置属性不再渲染标签，以"图标+名称"展示）
  - `src/components/Block/PropertyQuickEditor.vue`（project/area 的编辑弹层从纯文本输入升级为"搜索框 + 已有值列表"）
  - 关联 ADR：**ADR-0005**（Screen/View 查询模型）；查询注册表（`useBlockQueryRegistry`）的派生模式与本文一致。
- 来源：用户「优化属性里的项目显示内容」，经 grilling 收敛；随后用户确认同步改造 area。

---

## 背景 / 问题陈述

`project`（项目）与 `area`（领域）是块上的**内置字符串属性**（`types/property.ts`），值是自由文本，不指向任何实体。旧交互是：

1. **显示**：块底部属性区渲染 `项目: 📁 项目名称`——标签 + 图标 + 名称，信息冗余；
2. **编辑**：点击后弹层是纯文本输入框（`PropertyQuickEditor` 的 Text Input 分支），没有任何既有值可选，每次都要手输。

用户诉求：显示收敛为 `📁 项目名称`；点击弹层升级为"搜索框 + 已有项目列表"，可快捷复选历史值，仍可输入新值。

**为何需要 ADR**：仓库中没有"项目/领域"实体，也没有任何项目 store。把"已有值列表"做成**从全量块快照派生**而非引入实体/页面引用，是明确的数据模型取舍——后人看到"项目"列表却查不到 project 实体时，会困惑"为何不用页面引用"，须记录。

---

## 决策

### D1：project/area 保持自由字符串属性，不建实体、不建引用

值仍是普通字符串。**不**引入 Project 实体，**不**与 Page（`[[页面]]` wiki 链接）建立引用关系。弹层里的"已有值"只是**输入提示**（从历史值选一个填进去），不是关系选择器。用户选"已有值"与手输一个同名字符串，效果完全一致。

否决的备选：以 Page 作为项目（选中后 project 值存页面标题，图标取页面图标）。理由：语义变更大、引入新数据依赖，超出"输入提速"的需求边界。

### D2：已有值列表从 `blockCardStore.cards` 全量快照派生

对所有块的 `properties['project']`（或 `['area']`）取值：跳过非字符串/空白值 → 去重并计数 → **使用次数降序，同频按名称排序**。与 `useBlockQueryRegistry.customDefs`（从 cards 派生自定义字段）同源同模式。弹层打开时触发 `blockCardStore.getCards()` 保证快照就绪（懒加载/脏刷新由该 store 负责）。

已知语义：快照可能不含"脏卡片"（`refreshIfDirty` 会剔除），单个块独占的项目名可能在自编辑后短暂不出现，直至全量重载——接受，不为此改造 blockCardStore。

### D3：弹层交互 = 搜索框 + 列表 + 回车新建

- 搜索框自动聚焦并选中当前值；输入实时过滤（不区分大小写、包含匹配）；
- `↑/↓` 在列表中导航，`Enter` 选中高亮项；无高亮项时以输入内容创建新值（兼容旧自由输入行为）；`Esc` 关闭（BasePopover 原生）；
- 当前值在列表中高亮；列表为空时显示创建提示；
- 不提供"清除值"入口（块底部 hover `×` 删除属性已覆盖）。

### D4：bottom-of-block 的 icon-text 内置属性不再渲染标签

`PropertyDisplay` 对 `project`、`area` 只渲染 `图标 + 名称`（如 `📁 项目名`），标签 span 隐藏；其余属性（含自定义属性）保持 `标签: 值` 不变。选择器逻辑按 key 白名单（`project`/`area`）实现，未按 `displayStyle` 泛化——避免意外波及未来新增的 icon-text 属性。

---

## 后果

- 编辑成本下降：选历史值即填，回车可新建，两条路径并存；
- 数据语义不变：存量字符串值无需迁移，无实体/引用一致性负担；
- 列表新鲜度受块快照语义约束（见 D2 已知语义），可接受。
