# 0065 选区色块单层绘制

- Status: accepted
- Date: 2026-11-24
- 关联: ADR-0032（z-index 分层与 Teleport 铁律）、ADR-0035（跨块选区模型）

## Context

选区色是**一层半透明**（`--selection-bg`）。此前有两个绘制者，都以「逐单位各画一层」实现：

- 块选区：`.block.cb-selected::after`，每个被选中块一层 `inset: 0` 的伪元素。
- 文本选区：`.text-selection-rect`，`selectionClientRects` 每行一个 fixed 矩形。

两种做法都意味着**每一道内部边界都是两道独立边界**，各自抗锯齿。DPR 为整数时两层的覆盖率正好拼满一块像素，看不出来；DPR ≠ 1（Windows 125% / 150% 显示缩放、浏览器缩放）时边界落在分数设备像素上，同一像素上的覆盖率会差一点或多一点：

| 设备缩放 | 块边界处的取样（暗色主题，取样列在文字右侧空白处） |
|---|---|
| 100% | 无异常，整段同色 |
| 125% | `#353859`（不足一层 = 一条浅缝）、`#6C74CB`（超过一层 = 一条深线）交替出现 |

症状表现为选区内部横向的「缝隙」与「重叠」，随内容高度、字体、行高变化而移动位置，在表格（更多边界）与折行块（每行一条边界）上最明显。

## 决策

### D1 单一绘制者，迁到 body 级覆盖层

块选区不再用块内伪元素，改由 `BlockList` 渲染 `position: fixed` 的矩形（与文本选区同一套机制，Teleport 到 body，见 ADR-0032 铁律 2）。一个连续段只有一条矩形，段内不存在内部边界，缝与叠都无从产生。层级仍钉在 `$z-sticky - 1`：盖住块内全部内容（含 sticky 表头），但不染到 chrome（bullet/chevron = `$z-sticky + 2`、表格行列条、拖拽柄、文本选区矩形）。

`.cb-selected` 类保留为**状态标记**（表格行列条在选区态抑制等规则按它走），只是不再承载绘制。

### D2 合并判据刻意收紧

两个矩形合并的条件：左右缘相差 ≤ 0.5px **且** 纵向相接或重叠 ≤ 0.5px。

不采用「相邻矩形取并集包围盒」：跳块多选时它会把中间未选中的块一起涂上，嵌套子树也会被吃进父矩形，选区语义随之失真。

### D3 只取根选中块

参与测量的只有「自身被选中且没有选中祖先」的块，量 `.block` 外框（含子树全高）。嵌套子树由其父矩形覆盖；逐块再画只会叠出一层更深的色。

### D4 图片块不再例外

原来的「图片块选中不染色」例外一并下线：覆盖层是连续段，留一个洞等于在段中间开一道缝。图片块选中同样铺色。

### D5 文本选区的行矩形也在绘制环节合并

`selectionClientRects` 的契约保持「每行一个矩形」（工具条定位与既有单测都按它断言），压成单层发生在绘制：`mergeSelectionRects` 在 `BlockList` 里对行矩形再跑一次。相邻行、相邻块只要同缘相接就并成一条。

### D6 回归网挂在非整数 DPR 上

新增 Playwright project `dpr125`（`deviceScaleFactor: 1.25`）。100% 缩放下逐层绘制本来就是绿的，把它放在默认 project 里没有信号。

断言方式是「孤行检测」而不是「整段同色」：选区下面可能压着不同衬底（代码块底色、表头），那是合法的台阶；缺陷是**只有一行**与上下都不同、而上下彼此相同的尖刺行。另加一条结构断言：不存在「左右同缘且纵向相切」的两条矩形（即该合并的都合并了）。

## 已否决提案存档

- **保留逐块遮罩，只把边界对齐像素 / 相邻层重叠 0.5px**：实测 `top/bottom: -0.5px` 反而在每个块边界造出一条 1px 深线；对齐像素也挡不住字体、行高、内容变化引起的分数坐标，DPR 一变即复发。
- **遮罩改不透明等值色**（`color-mix(选区色 15% 压在页面底色上)`）：叠色确实消失（实测无异常行），但缝仍在——缝是「没画」，不透明救不了；而且会抹平代码块、表格单元格等不同衬底。
- **并集包围盒合并**：见 D2。

## 后果

- 覆盖层的几何需要在选中集合变化、滚动、resize、布局变更（侧栏开合）时重算；重挂载后补一次（选中集合没变时签名 watcher 不触发）。
- 新增像素级回归 spec 请挂到 `dpr125` project；默认 `chromium` project 用 `testIgnore` 排除它们。
- 逐块伪元素下线后，任何「按块画选区色」的新需求都要先确认能否并入覆盖层，否则会重新引入这一整类边界问题。
