# 选区包裹为页面引用（`[[页名]]`）— Spec

> 相关决策：ADR-0035（跨 block 文本选区模型）、ADR-0050（content 联动与建签门）、ADR-0032（浮层层级）
> 相关规范：`docs/3-features/link-spec.md`（`[[...]]` 解析规范 + §2.4 页名约束）
> 状态：已实施（Rust 建页门控 + 前端浮条 / e2e `tests/wrap-page-ref.spec.ts`）

## Problem Statement

用户通常先写自然语言，事后才想把其中某个名词升级成页面引用。当前三条路都要付额外成本：

| 路径 | 现状 | 缺口 |
|---|---|---|
| 手打 `[[ ]]` | `BracketPairExtension.handleTextInput` 在有选区时以 `[` 替换整个选区 | 选中的文字被吞，等于重打一遍 |
| `[[` 补全菜单 | 只按搜索词选页或建页，不读选区 | 同样要求重打 |
| 页面选择器 / 复制到新页 | 跨页往返 | 打断写作 |

结果是用户宁可保留纯文本，图谱密度与反链覆盖长期偏低。

同一语义下还有两个既存缺口：

1. **手打 `[[X]]` 不建页**。`ContentParseService::sync_links_for_block` 查不到目标页即跳过（`crates/comind-core/src/services/content_parse_service.rs:297` 注释与实现一致），`block_service.rs` 全程不触碰 Page 表。结果是引用存在、link 行不存在、反链与图谱缺边；页面要等用户点击链接（`useNavigateToPage`）才被创建。
2. **表格单元格不参与链接解析**。表格保存只写 `format.table`（`TableBlock.vue:511 flushSave`），`block.content` 不变，格内 `[[X]]` 永远进不了 link 表。

## Solution

在正文文本选区浮条（`InlineFormatToolbar`）末尾增加一个「转为页面引用」按钮：选区满足判据时，把选区文本包成 `[[页名]]`，先确保页面存在，再写回内容。

同批交付两个独立提交：

- 提交 A（后端）：提交时点建页 + 写 link，复用既有 `create_missing_tags` 门控。
- 提交 B（前端）：浮条按钮、判据、写回、收场；`link-spec.md` 增补页名约束；`createPage` / `renamePage` 接入校验。

## User Stories

1. 作为写作者，我选中一段已经写好的文字，点一次按钮就把它变成页面引用，不需要重打。
2. 作为写作者，我用双击选词或 Shift+方向选中文字时，同一个按钮也在，行为与拖拽选区一致。
3. 作为写作者，我拖选跨多个 block 时看不到这个按钮，因此不会得到一个语义不明的结果。
4. 作为写作者，选区里含 `|`、方括号或换行时按钮置灰，悬浮提示直接告诉我哪里不行，我改完就能用。
5. 作为写作者，包裹后页面立刻存在，反链与图谱当场成立，不需要我再去点一下链接。
6. 作为写作者，包裹后光标落在 `]]` 之后、浮条关闭，可以继续写下一句。
7. 作为写作者，我撤销这次包裹时内容回退，页面留在库里（避免撤销跨越内容与页面两层而产生半截状态）。
8. 作为写作者，我在中文句子中间包裹一个词，系统按既有 inline 单元规则补空格，与 `[[` 补全插页的字面一致。
9. 作为写作者，我手打 `[[不存在的页]]` 后失焦，页面会被创建，反链与图谱不再断边。
10. 作为写作者，我新建或重命名页面时若页名含非法字符，会看到具体原因和替换建议，而不是一个静默失败的页名。

## Implementation Decisions

### D1 入口与可见性

- 按钮位于 `InlineFormatToolbar` 的 `SelectionMarkRow` 之后，前置一道分隔线，图标用 `Brackets`（`lucide-vue-next`），尺寸沿用既有 28px 基线。
- **不进** `SelectionMarkRow`。该组件与表格范围菜单共用（`TableBlock.vue:2534`），下沉会把按钮泄漏到格/行列选区，而表格本期不支持（见 D11）。
- 单块内选区与跨 block 选区共用同一组件实例（range 模式，见 ADR-0035 D2）：跨 block 时按钮**不渲染**（能力永不成立，置灰会误导用户去改文本）。
- 编辑器模式（双击选词、Shift+方向、Ctrl+A）与 range 模式（拖拽 ≥4px，`BlockList.vue:120` 阈值）都必须支持，不允许按手势分化。

### D2 判据（双面检查）

页面引用仅在以下条件全部成立时可用：

1. **纯文本段**：选区的每个片段都落在 `renderSegments` 的 `text` 段内。覆盖 `[[X]]`、`#tag`、`@日期` 等已渲染单元的选区一律不合规——这些单元在编码层的原文带有语法字符，包裹会产出 `[[[[X]]]]` 这类断链，而屏幕上完全看不出来。
2. **字符合法**：编码层切片不含 `[`、`]`、`|` 与换行。
3. **非空**：`trim` 后非空；包裹时使用 `trim` 后的文本作为页名。

判据以单一函数实现，前端（置灰判定）与后端（`createPage` / `renamePage` 校验）共用同一份规则 fixture，防止两端漂移。

### D3 不合规处置

- 单块内 + 不合规 → 按钮置灰，`title` 只写判据本身，不写「不支持」，不写后果。判据有两类，文案分开，否则用户会被引到错误的修法上：
  - 覆盖已渲染单元：`选区覆盖了已渲染的链接/标签/日期，不能作为页面名`
  - 字面非法：`选区不能作为页面名：含 | [ ] 或换行，或只有空白`
- 跨 block → 不渲染。
- 编辑器模式与 range 模式表现一致。

### D4 建页与顺序

- 执行顺序：**先建页，再写文本**。与 `Editor.vue:279 handleWikiLinkSelect` 同序——顺序颠倒会让这次插入触发的 link 同步查不到目标页而丢边，且不会重试。
- 建页失败（离线 / 存储错误）→ 中止，不写文本，报错提示。不产生「文本已包裹但页面不存在」的中间态。
- 页面已存在 → 复用，不重复创建。

### D5 补空格

复用 `utils/inline-unit-pad.ts` 的 `padUnitForDoc`，与 `[[` 补全插页、`#tag`、`@日期` 同一份规则：

- 左邻是内容字符 → 左补一个空格；块首或已有空白 → 不补。
- 右邻非空白 → 右补一个空格。
- 紧跟 `((type))` / `（（type））` 收尾时左不补（否则 `))[[` 被劈开，关系语法整体失效）。

口径与「纯手打 `[[X]]`」不同（手打不补空），这是有意选择：本功能属于「插入新单元」语义，与补全插页同源；手打路径不经过 `padUnitForDoc`。

副产品：与补全插页一致，选区一直延伸到块尾时会留下一个尾随空格（`padInlineUnit` 的「行尾补尾空格」分支）。该空格属于单元的右缘带，用户随后一次 Backspace 即可整删（含 pad），不单独清理。

### D6 写回路径

**range 模式**（编辑器已失活，选区由 `BlockList` 持有）：

- 把 `stores/blocks.ts:1239 planTextRangeDeletion` 的裁剪思路扩成区间**替换**：复用 `normalizeTextRange` + `renderedOffsetToEncodedOffset` 换算到编码偏移，在 `block.content` 上拼接 `[[页名]]`。
- 选区始终在单块内（D1 已排除跨块），故只走「同块内」分支，不涉及多块合并。
- 插入的括号本身不带格式；插入点两侧的 marks 按切片保留，不扩张到括号上。插入点右侧 marks 的偏移按插入长度平移。
- 回写必须走 `updateBlockContent(..., { commitTags: true })`：只有提交语义才会建页与写 link。

**编辑器模式**：

- 读取 `editor.state.doc.textBetween(from, to)` 作为页名；
- `padUnitForDoc(state.doc, from, to, unit)` 计算补空结果；
- `insertContentAt({ from, to }, padded)` 一次替换（不拆成 delete + insert，理由见 `handleWikiLinkSelect` 注释：Enter 路径下 `tr.selection` 映射会落空）。

### D7 收场

- 包裹完成：结束选区、关闭浮条、光标落在 `]]` 之后。
- 不保留选区。保留会让浮条停在一个「内部已含括号」的选区上，按钮按判据又变灰，看起来像刚点完就坏了。

### D8 撤销

`Ctrl+Z` 只回退内容，页面保留。撤销不跨内容与页面两层做补偿：跨层补偿一旦失败会得到「只撤一半」的状态，比一个空页更难解释。空页可由回收站清理。

### D9 全局页名约束

- **定义落点**：`docs/3-features/link-spec.md` 新增「页名约束（建链准入）」小节，作为唯一权威定义。同时修正该文档现有自相矛盾：边界表声明 `[[页面#块ID]]` 合法，而同文件的 `INTERNAL_LINK_REG` 排除了 `#`；Rust 实现（`RE_INTERNAL` = `[^\]|]+?`）允许 `#`。以「允许 `#`」为准修正文档。
- **字集**：禁止 `[`、`]`、`|`、换行；`trim` 后非空；允许 `#`、空格、中文。与现有 Rust 解析正则完全一致，存量数据零影响。
- **执行层**：`createPage` 与 `renamePage` 同时校验，与按钮判据同源。存量页不追溯、不迁移。
- **拒绝表现**：拒绝并给出原因与替换建议（`|` → `·`、`[` → `（`、`]` → `）`）。不做静默清洗——用户要的页名被悄悄改掉会让跳转与反链都对不上预期。

### D10 提交 A：提交时点建页

- 复用 `create_missing_tags` 这条既有门控的语义（`block_service.rs:57`）：打字防抖传 `false` 不建页，提交（失焦、拆块、粘贴、整树保存）传 `true` 才建。标签当年就是靠它挡住 `#f` 中间态，页面走同一条门控，不引入新机制。
- 建页必须发生在 `sync_links_for_block` 之前，且与块保存同一事务；页面已存在（含软删行）时按既有 `UNIQUE(title)` 幂等规则复用/复活。
- 存量断链不主动修复：任意块下次保存即自愈；从未再编辑的块在点击链接时也会建页。不提供全库扫描命令（会把历史里误写的 `[[TODO]]`、`[[待定]]` 批量建成页）。

### D11 表格不做

表格保存只写 `format.table`，格内容不在 `block.content`；`Link` 实体只有 `source_block_id`，没有 cell 维度。要让格内 `[[X]]` 成立，三条备选路线都不属于「加按钮」量级，故另立项：

| 路线 | 做法 | 代价 |
|---|---|---|
| A | cell 变真 block（一格一块） | 表格布局模型重写（`merges`/`aligns`/`cellMarks`/行列增删/列宽/TSV/GFM 导出）、10×10 表 = 100 个编辑器 × 两态挂载、撤销与块选区并入、存量拆块迁移 |
| B | cell 保持字符串，共享渲染/解析 | `Link` 加 `source_cell`、格内 token 交互另写（`inline-unit-keyboard` 是 PM 插件不可复用）、结构变更同步 link 行 |
| C | 最小价值集：扫 rows 建页写 link，渲染可点 | 反链只能到块级、格内退格留半截括号、标签/日期不同步 |

## Testing Decisions

| 层 | 用例 |
|---|---|
| 判据函数（TS） | 合法 / 含 `\|` / 含 `[` `]` / 含换行 / 纯空白 / 覆盖 `#tag` / 覆盖 `[[X]]` / 覆盖 `@日期` |
| 判据双端一致 | 同一份 fixture 同时跑 TS 与 Rust 校验，断言结论相同 |
| range 替换 | 单块内替换后 `content` 正确；插入点两侧 marks 保留、括号无格式；补空规则五分支（块首 / 左邻内容 / 左邻空白 / 右邻空白 / `((type))` 后） |
| 编辑器模式 | `insertContentAt` 一次替换、光标落 `]]` 后、Enter 路径不丢内容 |
| 建页 | 页存在→复用；页不存在→建页 + link 行写入；建页失败→不写文本、报错 |
| 门控（Rust） | `create_missing = false`（打字）不建页；`true`（提交）建页并写边；`UNIQUE(title)` 幂等；软删页复活 |
| 浮条 | 单块合法→可点；单块非法→置灰 + `title` 文案；跨块→不渲染；键盘选区与拖拽同表现 |
| 收场 | 选区清空、浮条关闭、光标位置；`Ctrl+Z` 回退内容且页面保留 |
| 页面校验 | `createPage` / `renamePage` 拒绝非法字集并给建议；合法 `#`/空格/中文通过 |
| 回归 | `text-range`、`planTextRangeDeletion`、`InlineFormatToolbar`、`PageLinkMenu`、`BlockList.selection-orchestration` |

## Out of Scope

- 表格单元格链接子系统（见 D11，另立项）。
- 存量断链的批量补边。
- 改动 `BracketPairExtension` 的 `[` 按键行为（选中敲 `[` 仍替换选区）。
- 全局页名迁移与清洗。
- 别名页名（`[[目标|别名]]`）的输入支持。
- 页名长度上限。

## Further Notes

- 补空会使选区收场偏移 +2（或含空格 +3/+4），撤销快照与光标计算按新偏移处理。
- `planTextRangeDeletion` 扩成替换后，其既有回归是强约束：删除语义不得改变，只在同块分支上增加替换入口。
- 双面判据（D2）不能退化为「只看渲染文本」：用户看到 `X`、编码是 `[[X]]`，这是本功能最容易产出的静默断链。
